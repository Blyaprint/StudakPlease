# TECHNICAL — техническая архитектура

## Текущая известная основа

Проект использует Godot 4.6.

### Глобальное состояние и освещение

- `autoload/game_state.gd` — Autoload `GameState`.
- Известный сигнал: `light_mode_changed(is_lit: bool)`.
- Известное состояние: `is_lit_mode`.
- Ранее переключение было привязано к клавише L; согласованная целевая схема — переключение из экранной кнопки. Фактическое актуальное состояние скрипта нужно проверять перед реализацией.

### Окружение

- `scripts/environment_anim.gd` подписывается на `GameState.light_mode_changed` и переключает анимации окружения между состояниями света и темноты.

### Обычные NPC

- `scripts/npc.gd` содержит общую логику обычного посетителя.
- Известные методы: `walk_to_desk()`, `allow_pass()`, `deny_pass()`, `_leave()`.
- Известная группа: `npc`.

### Интерактивные предметы

- `scripts/interactable.gd` — базовый класс предметов, использующих систему наведения/взаимодействия.
- `scripts/hover_manager.gd` — управляет наведением для предметов группы `interactables`.
- Изученная ранее реализация `Interactable` ожидает среди непосредственных детей `AnimatedSprite2D` и `Polygon2D`; проверяет наведение через Polygon2D и управляет outline.
- Обычный UI `Button` не следует автоматически считать экземпляром этой системы: у UI-контролов собственные события наведения и нажатия. Экранная кнопка света должна использовать фактическую структуру UI-сцены.

### Рабочие сцены

- `scenes/main.tscn` — основная сцена.
- `scenes/desk/desk.tscn` — сцена стола с предметами.
- Из ранее проверенной версии стола: Monitor, Journal, Phone и Radio.
- Экранная кнопка была добавлена пользователем; последняя информация от пользователя — связь её скрипта исправлена в `main`. Точный текущий скрипт и SHA здесь не зафиксированы.

## Планируемая архитектура «Кривого»

Это план, не реализованный факт:

- `scripts/krivoy.gd` — отдельная логика аномалии.
- `scenes/krivoy.tscn` — отдельная сцена аномалии.
- Обычная логика `npc.gd` остаётся для обычных посетителей.
- Светом управляет `GameState`; UI-кнопка вызывает переключение состояния.
- Логика нейтрализации должна реагировать на выключение света только когда атака «Кривого» активна.

## Правила перед техническими изменениями

1. Перед правками получить свежие версии файлов и SHA именно из целевой feature-ветки.
2. Не предполагать структуру узлов по старым снимкам — проверить актуальные сцены и скрипты.
3. Сначала представить план изменений и зависимости.
4. Вносить код только после явного подтверждения пользователя.
5. Не заявлять о runtime-проверке, если проект фактически не запускался в Godot.
