# DEVELOPMENT — процесс разработки

## Репозиторий

- GitHub: [Blyaprint/StudakPlease](https://github.com/Blyaprint/StudakPlease).
- Основная ветка: `main`.
- Рабочая ветка задачи «Кривой»: `feature/krivoy-anomaly`.

## Обязательные правила Git

- Не коммитить рабочие изменения напрямую в `main`.
- Работать в соответствующих feature-ветках.
- Перед изменениями проверять актуальное состояние целевой ветки и SHA файлов.
- Не перезаписывать пользовательские изменения без согласования.
- После правок сверять diff и состояние веток.
- Слияние в `main` выполнять через согласованный Pull Request.

## Рабочий процесс механик

1. Изучить актуальные файлы и структуру проекта.
2. Обсудить поведение механики без изменения кода.
3. Согласовать архитектуру, список файлов и граничные случаи.
4. Зафиксировать подтверждённые решения в `docs/DECISIONS.md`.
5. Получить явное разрешение на реализацию.
6. Реализовать в feature-ветке.
7. Проверить diff и доступные тесты; честно указать, запускался ли Godot.
8. Обновить документацию и подготовить PR, когда пользователь попросит.

## Текущий этап

- Общая система маршрутов обычных NPC реализована в `feature/krivoy-anomaly`.
- Посетители создаются контроллером в `scripts/main.gd`; одновременно активен только один посетитель.
- Следующий посетитель случайно выбирается между обычным NPC и «Кривым».
- Для «Кривого» добавлены отдельные `scripts/krivoy.gd` и `scenes/krivoy.tscn`, таймеры проявления/атаки/защиты, уход после успешной защиты и базовый Game Over.
- «Кривой» не входит в группу `npc`, поэтому клавиши `Space` и `Esc` не вызывают его обычные действия.
- Пользователь проверил основные сценарии непосредственно в Godot 4.6: маршруты обычных NPC, смену и фиксацию маршрутов, единственность активного посетителя, проявление в темноте, а также полный цикл «Кривого» вплоть до успешной защиты и Game Over. Все перечисленные сценарии подтверждены как работающие.
- Для «Кривого» реализовано пугающее появление после полного проявления: рывок, тряска игрового мира и нависание; таймер атаки запускается после завершения эффекта.
- Выключение света до начала тряски ставит появление на паузу; выключение после начала тряски отменяет остаток эффекта и сразу переводит «Кривого» в фазу защиты.
- При выключении света во время фазы атаки спрайт «Кривого» немедленно возвращается к исходным позиции, масштабу и повороту; параметры самого эффекта появления сохранены.
- По замечаниям пользователя исправлена тряска: теперь синхронно смещаются корневой `Node2D` и `offset` всех `CanvasLayer`, чтобы тряслось всё изображение игрового окна. Спрайт мгновенно увеличивается до масштаба рывка, сигнал запускает тряску в том же кадре, а обработчик сразу применяет первый экранный сдвиг без ожидания шага tween.
- Пользовательские параметры прыжкового бега перенесены в дефолты `scripts/krivoy.gd`; соответствующие переопределения удалены из `scenes/krivoy.tscn`. Спрайт опущен по локальной оси Y на 8 пикселей.
- Новые сценарии пока не проверены в Godot 4.6: движок в доступной среде не установлен.
- Добавлены зацикленные звуки шагов для обычных NPC и «Кривого»: маршруты, назначение файлов и остановка описаны в `docs/GDD.md` и `docs/TECHNICAL.md`.
- Изменения звука шагов после внесения ещё не проверялись в Godot 4.6; движок в доступной среде не установлен.
- Единая длительность подхода для всех посетителей задаётся через `visitor_approach_duration` в Inspector главной сцены (по умолчанию 2,4 секунды). Перемещение и рост масштаба используют это время; множитель ×2 у «Кривого» ускоряет только прыжковый цикл. Реализация ожидает проверки в Godot 4.6.
- После игровой проверки остаётся подобрать окончательные значения параметров по фактическому игровому виду.
