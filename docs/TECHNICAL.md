# TECHNICAL — техническая архитектура

## Текущая известная основа

Проект использует Godot 4.6.

### Глобальное состояние и освещение

- `autoload/game_state.gd` — Autoload `GameState`.
- Сигнал: `light_mode_changed(is_lit: bool)`.
- Состояние: `is_lit_mode`.
- Метод `GameState.toggle_light()` переключает состояние освещения, выводит его в лог и отправляет сигнал `light_mode_changed`.
- Переключение вызывается нажатием на интерактивную кнопку стола; клавиша L больше не используется.

### Окружение и ночной слой

- `scripts/environment_anim.gd` подписывается на `GameState.light_mode_changed` и переключает анимации окружения между состояниями света и темноты.
- `scripts/main.gd` подписывается на тот же сигнал и управляет видимостью узла `NightOverlay`: слой видим при выключенном свете и скрыт при включённом.
- `scenes/ui/night_overlay.tscn` содержит экранный `CanvasLayer` с шейдерным затемнением. Сам эффект включается и выключается через видимость инстанса в основной сцене.

### Обычные NPC

- `scripts/npc.gd` содержит общую логику обычного посетителя.
- Известные методы: `walk_to_desk()`, `allow_pass()`, `deny_pass()`, `_leave()`.
- Известная группа: `npc`.
- NPC подписывается на `GameState.light_mode_changed`.
- Прогресс цветового проявления хранится отдельно от tween движения и альфа-канала.
- Tween проявления работает непрерывно и не ставится на паузу при выключении света.
- Видимый цвет вычисляется с учётом двух независимых факторов: текущего прогресса проявления и состояния света. При выключенном свете RGB немедленно соответствует `shadow_color`; прогресс при этом продолжает обновляться.
- При включении света NPC сразу отображает актуальный уровень прогресса проявления — ожидания или повторного отсчёта нет.
- При начале ухода tween проявления останавливается, чтобы не конфликтовать с анимацией ухода в тень.

#### Выбор и фиксация маршрута

- `Route.NONE`, `Route.TO_DESK` и `Route.PASSING` описывают текущее состояние маршрута.
- При включённом свете выбирается маршрут к `wait_pos`; при выключенном — проход к `exit_right_pos`.
- Пока маршрут не зафиксирован, сигнал `GameState.light_mode_changed` может переключить цель движения. Текущий tween останавливается, а новый начинается из текущих позиции и масштаба NPC.
- `desk_route_lock_x` (по умолчанию `35.0`) фиксирует маршрут к стойке при достижении соответствующей координаты X.
- `pass_route_lock_x` (по умолчанию `500.0`) фиксирует проход мимо при достижении соответствующей координаты X.
- Пороги экспортированы в Inspector. X измеряется в локальной системе координат родительского узла NPC.
- При обработке сигнала света сначала проверяется пересечение порога текущего маршрута, чтобы смена света не обошла фиксацию.
- После фиксации последующие переключения света не меняют маршрут.
- После завершения маршрута к стойке вызывается обычная логика прибытия и показа диалога. После завершения прохода мимо NPC удаляется без прибытия к стойке.
- На маршруте прохода мимо альфа NPC устанавливается в `1.0`, чтобы он был виден как тёмный силуэт даже при выключенном свете; плавное исчезновение начинается только на последней половине пути к `exit_right_pos`.

### Интерактивные предметы

- `scripts/interactable.gd` — базовый класс предметов, использующих систему наведения/взаимодействия.
- `scripts/hover_manager.gd` — управляет наведением для предметов группы `interactables`.
- `Interactable` ожидает среди непосредственных детей `AnimatedSprite2D` и `Polygon2D`; проверяет наведение через Polygon2D и управляет outline.
- `scenes/desk/button.tscn` — интерактивная кнопка стола, подключённая к `scripts/button.gd`.
- `scripts/button.gd` переопределяет `_interact()` и вызывает `GameState.toggle_light()`.

### Рабочие сцены

- `scenes/main.tscn` — основная сцена.
- `scenes/desk/desk.tscn` — сцена стола с предметами Monitor, Journal, Phone, Radio и Button.
- Кнопка стола инстанцируется в `desk.tscn`; отдельная UI-кнопка Godot для переключения света не используется.
- В инстансе NPC в `scenes/main.tscn` настроены пороги `desk_route_lock_x = 35.0` и `pass_route_lock_x = 500.0`.

## Планируемая архитектура «Кривого»

Это план, не реализованный факт:

- `scripts/krivoy.gd` — отдельная логика аномалии.
- `scenes/krivoy.tscn` — отдельная сцена аномалии.
- Обычная логика `npc.gd` остаётся для обычных посетителей.
- Светом управляет `GameState`; интерактивная кнопка стола вызывает `GameState.toggle_light()`.
- Логика нейтрализации должна реагировать на выключение света только когда атака «Кривого» активна.

## Правила перед техническими изменениями

1. Перед правками получить свежие версии файлов и SHA именно из целевой feature-ветки.
2. Не предполагать структуру узлов по старым снимкам — проверить актуальные сцены и скрипты.
3. Для новых механик сначала представить план и получить явное подтверждение пользователя.
4. Не заявлять о runtime-проверке, если проект фактически не запускался в Godot.
