# DEVELOPMENT — процесс разработки

## Репозиторий

- GitHub: [Blyaprint/StudakPlease](https://github.com/Blyaprint/StudakPlease).
- Основная ветка: `main`.
- Рабочая ветка задачи «Кривой»: `feature/krivoy-anomaly`.

## Обязательные правила Git

- Не коммитить рабочие изменения напрямую в `main`.
- Работать в соответствующей feature-ветке.
- Перед изменениями проверять актуальное состояние целевой ветки.
- Не перезаписывать пользовательские изменения без согласования.
- После завершения сверять diff, коммиты и состояние веток.
- Слияние в `main) выполнять через согласованный Pull Request.

## Рабочий процесс механик

1. Изучить актуальные файлы и структуру проекта.
2. Обсудить поведение механики без изменения кода.
3. Согласовать архитектуру, список файлов и граничные случаи.
4. Зафиксировать решения в `docs/DECISIONS.md`.
5. Получить явное «ОК» на реализацию.
6. Реализовать в feature-ветке.
7. Проверить diff и доступные тесты; честно указать, запускался ли Godot.
8. Обновить документацию и подготовить PR, когда пользователь попросит.

Обсуждается реализация аномалии «Кривой». Экранная кнопка света добавлена пользователем; пользователь сообщил, что исправил связку скрипта в `main`. Синхронизация этой последней правки в feature-ветку отдельно не подтверждена в этой записи.
